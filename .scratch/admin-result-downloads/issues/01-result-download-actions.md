# 01: ย้ายปุ่มดาวน์โหลดมาแถว Document / Fields

**What to build:** ให้ Admin และ Viewer ดาวน์โหลดเอกสารที่บันทึกแล้วจากแถว Document / Fields ในหน้ารายละเอียด Results ได้โดยไม่ต้องกลับไปหาปุ่มในการ์ดด้านบน ย้ายปุ่มเดิมมาเพียงชุดเดียว แสดงเฉพาะ Response ปัจจุบันที่ส่งแล้ว XLSX Form ใช้ปุ่ม Excel และ PDF ส่วน DOCX Form ใช้ปุ่ม DOCX และ PDF ไฟล์ต้องตรงกับ Submission และ Revision ที่เลือกดู พร้อม regression และคู่มือระบบที่อธิบายพฤติกรรมจริง

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] ย้ายปุ่มส่งออกสองปุ่มจากการ์ดด้านบนมาอยู่ด้านขวาของแถว Document / Fields ไม่มีปุ่มส่งออกชุดเดิมเหลือซ้ำ
- [ ] XLSX Form แสดง “ดาวน์โหลด Excel” และ “ดาวน์โหลด PDF” และได้ไฟล์ชนิดที่เลือก ส่วน DOCX Form แสดง “ดาวน์โหลด DOCX” และ “ดาวน์โหลด PDF” โดยไม่แสดงหรือเพิ่มการแปลงเป็น Excel
- [ ] แสดงปุ่มเฉพาะ Response ที่ปัจจุบันเป็น submitted ไม่ใช่พิจารณาจากสถานะเผยแพร่ของ Form เพียงอย่างเดียว
- [ ] Draft ปัจจุบันไม่มีปุ่มส่งออกทั้งสอง รวมกรณีเคยมี Submission แล้วเปิด Draft รอบใหม่ โดยไม่เปลี่ยนความสามารถในการอ่าน Submission เก่าจากหน้าอื่น
- [ ] ดาวน์โหลดเอกสารต้นฉบับและ PDF ตาม Submission และ Revision ที่เลือก ทั้ง Original และ Correction เก่า ไม่เปลี่ยนเป็นรุ่นล่าสุดเมื่อส่งออก และไม่เปลี่ยนการเลือก Revision เริ่มต้นเดิม
- [ ] สลับ Document และ Fields แล้วยังใช้ปุ่มส่งออกชุดเดียวกันได้ เก็บ Revision selector และคำสั่ง Correction ไว้ตำแหน่งเดิม
- [ ] Admin และ Viewer ใช้ปุ่มได้ตามสิทธิ์เดิม Viewer ไม่ได้รับคำสั่ง Correction หรือลบคำตอบเพิ่ม และไม่เปลี่ยนการตรวจสิทธิ์ฝั่ง API
- [ ] ใช้ Button กลางและรูปแบบ secondary ขนาดเล็กตามหน้า fill ใช้ component แสดงผลกลางโดยเพิ่มช่อง actions แบบ optional ไม่สร้างระบบส่งออก ชุดปุ่มกลาง หรือ dependency ใหม่
- [ ] component แสดงผลกลางจัด layout และแท็บเท่านั้น กติกาสถานะ สิทธิ์ Revision และคำขอส่งออกยังอยู่กับหน้ารายละเอียด Results
- [ ] วางปุ่มดาวน์โหลดนอกกลุ่ม tablist จอแคบตัดบรรทัดได้โดยไม่ล้นแนวนอน Tab เข้าถึงและกดปุ่มได้ และ ArrowLeft / ArrowRight ยังสลับแท็บตามเดิม
- [ ] เมื่อประวัติรุ่นยังไม่พร้อม โหลดล้มเหลว หรือไม่พบรุ่นที่เลือก ปุ่มถูกปิดตามกลไกเดิม ไม่ส่งออกจากรุ่นที่ยังยืนยันไม่ได้
- [ ] ป้องกันคำขอซ้ำขณะกำลังส่งออก เมื่อสำเร็จหรือล้มเหลวปลดสถานะ busy ตามกลไกเดิม เมื่อเกิดข้อผิดพลาดผู้ใช้เห็นข้อความและกดลองใหม่ได้
- [ ] ใช้ handler, API ส่งออก, ชื่อไฟล์ และพารามิเตอร์ Revision เดิม ไม่เพิ่ม API หรือ schema และไม่ยกกลไกจับสำเนาจาก editor ของหน้า fill มาใช้
- [ ] การดาวน์โหลดทั้งสำเร็จและล้มเหลวไม่บันทึก Draft ไม่ส่งคำตอบ ไม่แก้ข้อมูลต้นทาง และไม่ย้อนสถานะ Submission เมื่อแปลง PDF ไม่สำเร็จ
- [ ] หน้ารายละเอียด Submission อีกหน้าที่ใช้ component กลางร่วมกันยังแสดงแท็บและใช้ปุ่มส่งออกเดิมได้ โดยไม่ได้รับปุ่มเพิ่มหรือการเปลี่ยนพฤติกรรม
- [ ] ต่อ integration test UI เดิมผ่านหน้ารายละเอียด Results เป็น seam หลัก ครอบคลุม Admin/Viewer, XLSX/DOCX, submitted/Draft, Original/Correction, ประวัติรุ่นที่ยังไม่พร้อม, busy, failure และ retry ตามพฤติกรรมข้างต้น ใช้ fixtures สังเคราะห์และไม่ทดสอบ props, state ภายใน, source text หรือข้อความล้วนโดยแยกจากพฤติกรรม
- [ ] ตรวจผ่านเบราว์เซอร์จริงด้วยข้อมูลทดสอบ เปิดไฟล์ XLSX, DOCX และ PDF ที่ดาวน์โหลดเพื่อตรวจค่าที่ต่างกันระหว่าง Original กับ Correction ไม่ถือว่า URL คำขอหรือ mock blob เป็นหลักฐานเนื้อหาไฟล์จริง
- [ ] ตรวจภาพแถวปุ่มบนจอกว้างและจอแคบ ตรวจคีย์บอร์ดและการสลับแท็บ รวมถึงหน้ารายละเอียด Submission อีกหน้าที่ใช้ component ร่วมกัน พร้อมรายงานสิ่งที่ตรวจจริงและข้อจำกัดที่ยังไม่ได้ตรวจ
- [ ] รัน regression ของ UI ที่เกี่ยวข้องและชุด UI รวม รวมถึงชุดตารางผลลัพธ์ Spreadsheet เดิม ตรวจ format, lint และ types ตาม scripts ของโครงการก่อนส่งมอบ
- [ ] อัปเดตตารางหน้าและคำอธิบาย Results ในคู่มือระบบพร้อม implementation ทบทวนแผนภาพและ source references ที่ได้รับผลกระทบ อัปเดตวันที่และ baseline ตาม workflow สร้างและตรวจ generated outputs และเปิด HTML ตรวจเนื้อหา ลิงก์ แผนภาพ และการซูมที่เกี่ยวข้อง
- [ ] ไม่เปลี่ยนพฤติกรรมหน้า fill, receipt, รายการ Results และการกรองตาม ADR 0004 รวมถึงการบันทึก Draft, Submit, Correction และการลบข้อมูลนอกขอบเขตการย้ายปุ่มนี้
