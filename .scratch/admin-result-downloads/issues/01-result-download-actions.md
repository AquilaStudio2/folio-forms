# 01: ย้ายปุ่มดาวน์โหลดมาแถว Document / Fields

**What to build:** ให้ Admin และ Viewer ดาวน์โหลดเอกสารที่บันทึกแล้วจากแถว Document / Fields ในหน้ารายละเอียด Results ได้โดยไม่ต้องกลับไปหาปุ่มในการ์ดด้านบน ย้ายปุ่มเดิมมาเพียงชุดเดียว แสดงเฉพาะ Response ปัจจุบันที่ส่งแล้ว XLSX Form ใช้ปุ่ม Excel และ PDF ส่วน DOCX Form ใช้ปุ่ม DOCX และ PDF ไฟล์ต้องตรงกับ Submission และ Revision ที่เลือกดู พร้อม regression และคู่มือระบบที่อธิบายพฤติกรรมจริง

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] ย้ายปุ่มส่งออกสองปุ่มจากการ์ดด้านบนมาอยู่ด้านขวาของแถว Document / Fields ไม่มีปุ่มส่งออกชุดเดิมเหลือซ้ำ
- [x] XLSX Form แสดง “ดาวน์โหลด Excel” และ “ดาวน์โหลด PDF” และได้ไฟล์ชนิดที่เลือก ส่วน DOCX Form แสดง “ดาวน์โหลด DOCX” และ “ดาวน์โหลด PDF” โดยไม่แสดงหรือเพิ่มการแปลงเป็น Excel
- [x] แสดงปุ่มเฉพาะ Response ที่ปัจจุบันเป็น submitted ไม่ใช่พิจารณาจากสถานะเผยแพร่ของ Form เพียงอย่างเดียว
- [x] Draft ปัจจุบันไม่มีปุ่มส่งออกทั้งสอง รวมกรณีเคยมี Submission แล้วเปิด Draft รอบใหม่ โดยไม่เปลี่ยนความสามารถในการอ่าน Submission เก่าจากหน้าอื่น
- [x] ดาวน์โหลดเอกสารต้นฉบับและ PDF ตาม Submission และ Revision ที่เลือก ทั้ง Original และ Correction เก่า ไม่เปลี่ยนเป็นรุ่นล่าสุดเมื่อส่งออก และไม่เปลี่ยนการเลือก Revision เริ่มต้นเดิม
- [x] สลับ Document และ Fields แล้วยังใช้ปุ่มส่งออกชุดเดียวกันได้ เก็บ Revision selector และคำสั่ง Correction ไว้ตำแหน่งเดิม
- [x] Admin และ Viewer ใช้ปุ่มได้ตามสิทธิ์เดิม Viewer ไม่ได้รับคำสั่ง Correction หรือลบคำตอบเพิ่ม และไม่เปลี่ยนการตรวจสิทธิ์ฝั่ง API
- [x] ใช้ Button กลางและรูปแบบ secondary ขนาดเล็กตามหน้า fill ใช้ component แสดงผลกลางโดยเพิ่มช่อง actions แบบ optional ไม่สร้างระบบส่งออก ชุดปุ่มกลาง หรือ dependency ใหม่
- [x] component แสดงผลกลางจัด layout และแท็บเท่านั้น กติกาสถานะ สิทธิ์ Revision และคำขอส่งออกยังอยู่กับหน้ารายละเอียด Results
- [x] วางปุ่มดาวน์โหลดนอกกลุ่ม tablist จอแคบตัดบรรทัดได้โดยไม่ล้นแนวนอน Tab เข้าถึงและกดปุ่มได้ และ ArrowLeft / ArrowRight ยังสลับแท็บตามเดิม
- [x] เมื่อประวัติรุ่นยังไม่พร้อม โหลดล้มเหลว หรือไม่พบรุ่นที่เลือก ปุ่มถูกปิดตามกลไกเดิม ไม่ส่งออกจากรุ่นที่ยังยืนยันไม่ได้
- [x] ป้องกันคำขอซ้ำขณะกำลังส่งออก เมื่อสำเร็จหรือล้มเหลวปลดสถานะ busy ตามกลไกเดิม เมื่อเกิดข้อผิดพลาดผู้ใช้เห็นข้อความและกดลองใหม่ได้
- [x] ใช้ handler, API ส่งออก, ชื่อไฟล์ และพารามิเตอร์ Revision เดิม ไม่เพิ่ม API หรือ schema และไม่ยกกลไกจับสำเนาจาก editor ของหน้า fill มาใช้
- [x] การดาวน์โหลดทั้งสำเร็จและล้มเหลวไม่บันทึก Draft ไม่ส่งคำตอบ ไม่แก้ข้อมูลต้นทาง และไม่ย้อนสถานะ Submission เมื่อแปลง PDF ไม่สำเร็จ
- [x] หน้ารายละเอียด Submission อีกหน้าที่ใช้ component กลางร่วมกันยังแสดงแท็บและใช้ปุ่มส่งออกเดิมได้ โดยไม่ได้รับปุ่มเพิ่มหรือการเปลี่ยนพฤติกรรม
- [x] ต่อ integration test UI เดิมผ่านหน้ารายละเอียด Results เป็น seam หลัก ครอบคลุม Admin/Viewer, XLSX/DOCX, submitted/Draft, Original/Correction, ประวัติรุ่นที่ยังไม่พร้อม, busy, failure และ retry ตามพฤติกรรมข้างต้น ใช้ fixtures สังเคราะห์และไม่ทดสอบ props, state ภายใน, source text หรือข้อความล้วนโดยแยกจากพฤติกรรม
- [x] ตรวจผ่านเบราว์เซอร์จริงด้วยข้อมูลทดสอบ เปิดไฟล์ XLSX, DOCX และ PDF ที่ดาวน์โหลดเพื่อตรวจค่าที่ต่างกันระหว่าง Original กับ Correction ไม่ถือว่า URL คำขอหรือ mock blob เป็นหลักฐานเนื้อหาไฟล์จริง
- [x] ตรวจภาพแถวปุ่มบนจอกว้างและจอแคบ ตรวจคีย์บอร์ดและการสลับแท็บ รวมถึงหน้ารายละเอียด Submission อีกหน้าที่ใช้ component ร่วมกัน พร้อมรายงานสิ่งที่ตรวจจริงและข้อจำกัดที่ยังไม่ได้ตรวจ
- [x] รัน regression ของ UI ที่เกี่ยวข้องและชุด UI รวม รวมถึงชุดตารางผลลัพธ์ Spreadsheet เดิม ตรวจ format, lint และ types ตาม scripts ของโครงการก่อนส่งมอบ
- [x] อัปเดตตารางหน้าและคำอธิบาย Results ในคู่มือระบบพร้อม implementation ทบทวนแผนภาพและ source references ที่ได้รับผลกระทบ อัปเดตวันที่และ baseline ตาม workflow สร้างและตรวจ generated outputs และเปิด HTML ตรวจเนื้อหา ลิงก์ แผนภาพ และการซูมที่เกี่ยวข้อง
- [x] ไม่เปลี่ยนพฤติกรรมหน้า fill, receipt, รายการ Results และการกรองตาม ADR 0004 รวมถึงการบันทึก Draft, Submit, Correction และการลบข้อมูลนอกขอบเขตการย้ายปุ่มนี้

## Comments

ดำเนินการครบวันที่ 9 พฤศจิกายน 2026 บน integration branch `codex/admin-result-downloads` โดยใช้ worktree แยกสำหรับ implementation และการแก้ review ไม่แก้ parent spec และไม่ push หรือเปิด PR

- TDD: regression ส่งออกตาม Revision fail ก่อนย้ายปุ่ม และผ่านหลัง implementation ชุดเฉพาะงานผ่าน 50 tests
- Standards review และ Spec review พบ guard ห้ามลบระหว่างดาวน์โหลดถูกถอดออกโดยไม่ตั้งใจ คืน guard เดิมใน `95534c9` พร้อม regression ที่ fail ก่อนแก้และ pass หลังแก้ ผู้ตรวจทั้งสองแกนยืนยันไม่เหลือข้อค้นพบ
- ตรวจผ่านเบราว์เซอร์กับ backend และ ONLYOFFICE จริง เปิดอ่านไฟล์ดาวน์โหลด 20 ไฟล์ ครอบคลุมสองบทบาท สองชนิดเอกสาร Original, Correction เก่า และ PDF รวมการกด Enter และการดาวน์โหลดจากหน้ารายละเอียด Submission อีกหน้า
- เทียบ Response, Submission, Correction และ SHA-256 ของเอกสารก่อน/หลัง 17 การดาวน์โหลดจาก Results แล้วเหมือนเดิม ตรวจซ้ำกับคำขอ PDF ที่หน่วงไว้เพื่อยืนยันว่าปุ่มลบและส่งออกถูกปิดระหว่างรอ และกลับมาใช้ได้หลังเสร็จ โดยข้อมูลต้นทางไม่เปลี่ยน
- ตรวจ Draft รอบใหม่ที่ยังมี Submission เก่าแล้วทั้ง Admin และ Viewer ไม่มีปุ่มส่งออก ตรวจภาพที่ความกว้าง 320, 375 และ 1365 พิกเซล พร้อมคีย์บอร์ดและการตัดบรรทัด ไม่พบการล้นแนวนอน
- Full UI รอบแรกรันปกติผ่าน 226 tests รอบตรวจหลังแก้ review ที่รันคู่กับการสร้างภาพคู่มือมี 5 failures ในเทสต์บัญชีเดิม โดยกรณีแรก timeout ที่ 15000 ms กรณีแรกนั้นผ่านเมื่อรันแยก จากนั้นรันครบทั้ง 18 ไฟล์ด้วย `--maxWorkers=2` หลังสร้างภาพเสร็จ ผ่าน 226 tests ไม่ข้ามกรณีและไม่แก้ timeout หรือ config ถาวร สาเหตุ resource contention เป็นข้อสันนิษฐาน ไม่ใช่ผลจาก profiling
- Root format/lint และ types ผ่าน Web production build ผ่าน Workflow build/check ผ่านทั้ง 23 แผนภาพ เปิด HTML ตรวจตารางหน้า หัวข้อ Results แผนภาพ ลิงก์ source และ zoom controls แล้ว
- ลบข้อมูลและ object files ของ fixture สังเคราะห์ รวมถึงสคริปต์และสภาพแวดล้อมอ่าน PDF ชั่วคราวแล้ว ไม่เปลี่ยนข้อมูลจริงของผู้ใช้หรือการแก้ไขอื่นที่เกิดขึ้นพร้อมกัน

ข้อจำกัด: ไม่ทดสอบ PDMS, OmniRoute, deployment หรือ server HTTP suite เต็ม เพราะไม่มีการเปลี่ยน API หรือ flow เหล่านั้น ลิงก์ source ในคู่มืออ้าง commit บน branch นี้และจะใช้ผ่าน remote ได้เมื่อ push แล้ว

การ cleanup ไม่ลบ Audit Trail แบบ append-only และไม่ปิด trigger ของระบบแบบ global การลบ metadata ที่ immutable ของ fixture ใช้ transaction แยกซึ่งจำกัดเฉพาะ IDs ที่สร้างเพื่อการตรวจครั้งนี้
