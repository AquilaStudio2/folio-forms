### Tracker และ next frontier

- Map เป็น index เท่านั้น รายละเอียดอยู่ใน child tickets ใต้ `issues/` ซึ่งมี `Parent: ../map.md` ใช้ Labels เฉพาะ `wayfinder:*`; ไม่มี Status คือเปิด และ Assignee ว่างคือยังไม่ claim ตาม [convention เดิม](../ecm-attachments/map.md#วิธีทำงานใน-local-markdown-tracker)
- หา frontier จาก children ที่ไม่มี Status, Assignee ว่าง และ blockers ทุกตัว resolved แล้ว เรียงหมายเลขชื่อไฟล์; `Blocked by` ใช้เลข local effort นี้ ไม่ใช้ triage labels
- ปิด decision ครบ 9 ตั๋ว ไม่มี open/claimed child หรือ frontier ที่ต้องถามต่อใน map นี้แล้ว ดู [ทบทวน HOLD หลังปิด safety map](../ecm-storage-templates/planning.md#ทบทวน-hold-หลังปิด-safety-map) สำหรับ implementation/evidence ที่ยังขาด การปิด decision ไม่ใช่การอนุญาต execution/live calls หรือ release acceptance
- ลำดับทำงานล่าสุด: คุย child decisions ที่เหลือให้ครบก่อน แล้วทบทวน remaining HOLD จาก Resolution ล่าสุดของแต่ละตั๋วครั้งเดียว ไม่เปิดรายการคำถาม HOLD ซ้ำขนานกับ tickets ประเด็นที่เคลียร์ด้วย policy/risk acceptance ให้ระบุว่าปลด gate ใด ส่วนที่ยังต้อง implementation หรือผลทดสอบ/provider evidence ให้เหลือเฉพาะ prerequisite ที่ยังขาดจริง ไม่ใช้ checklist/ข้อเสนอเก่าลบล้างคำตัดสินใหม่ และไม่ถือว่าการปิด planning ticket เป็นผลทดสอบผ่าน
- Charting นี้ไม่ claim ไม่ resolve และไม่ถือคำถามหรือแนวแนะนำว่าได้รับอนุมัติ คำตอบต้องเกิดจาก human/provider ใน session ถัดไป ไม่สร้าง research branch/push เพื่อจัดหมวดคำถาม

## Out of scope

- การแก้ code, schema, migration, เปลี่ยน Forms/Responses, ทดลอง API จริงนอกขอบเขตที่ผู้ใช้อนุมัติใน [หลักฐานยุติ unknown upload และ DELETE ที่เชื่อถือได้](issues/06-unknown-settlement-contract.md#2026-11-18--pyw1tt--อนุญาต-scoped-live-api-และผลตรวจจริง), push หรือ deploy
- Implementation naming/receipt/guard, schema/persistence changes หรือแก้ old-data ก่อนอนุมัติพัฒนา อนุญาตเฉพาะอัปเดต intended contract ตาม human decisions ในเอกสาร ไม่แตก naming contract ซ้ำใน map
- การเปิดคำถามเดิมเรื่อง DCM-only originals, หนึ่งไฟล์ต่อ slot, public-link/private-storage redesign, legacy UUID/Published contracts, category-label-to-folder equivalence หรือการมี wildcard routing
- การประกาศ Production เสียหายจาก local reproduction หรือประกาศ provider/release ผ่านจาก source, test double, HTTP 200, token ต่างกัน หรือจำนวน tests เพียงอย่างเดียว
- การเทียบ upload/download bytes และ aggregate-capacity workload ในแผน type/size ต่อช่อง ตามขอบเขตที่ผู้ใช้ตัดใน [หลักฐาน provider รองรับ original files ทุกชนิด ขอบเขตขนาด และ capacity](issues/08-provider-type-size-capacity.md#resolution--pyw1tt--อนุมัติแผนชนิดไฟล์และขนาดต่อช่อง) ไม่ใช่การยกเลิก product limits/runtime integrity หรือรับรอง unlimited capacity
