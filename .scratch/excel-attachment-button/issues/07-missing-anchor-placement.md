## อาการและหลักฐาน

ฟอร์มทดสอบ `e43f39118450457c95d2c21b9b5b60ee` เลือก D13 แล้ววางปุ่มไม่ได้ ข้อความเดิมบอกเพียงว่าตำแหน่งช่องเดิมไม่ครบ

attachment_6 ถูกสร้างที่ D15 ระหว่างทดสอบก่อนหน้านี้ แต่ยังไม่ได้บันทึกต้นแบบหลังเลือกไฟล์ในหน่วยความจำ ส่วนตำแหน่งที่ต้องการของ attachment_7 ยังต้องให้ผู้ใช้ระบุ ห้ามเดาหรือทิ้ง metadata ของช่อง

## ตรวจรับ

- อ่านรายชื่อตำแหน่งให้ครบตาม binding ปัจจุบันก่อนตรวจการวางปุ่ม
- metadata เก่าที่ถูกลบแล้วไม่ทำให้เกิดการปฏิเสธผิดพลาด
- หากช่องยังอยู่แต่ตำแหน่งหายจริง ให้หยุดการวางปุ่ม พร้อมระบุชื่อ/tag และวิธีผูกตำแหน่งใหม่
- คงการตรวจตำแหน่งซ้อนและป้องกันการเขียนผิดช่อง
- regression tests ต้องครอบคลุมทั้งตำแหน่งหายจริงและข้อมูลเก่า
- การผูกกลับในฟอร์มนี้ต้องใช้ตำแหน่งที่ผู้ใช้ยืนยัน

## ผลตรวจ

แก้การอ่าน anchor ให้ครบทุกครั้งและตรวจ metadata ใหม่ก่อนปฏิเสธ เพิ่มชื่อ/tag ที่หายพร้อมขั้นตอนผูกกลับทั้งข้อความผิดพลาดและแผง ช่องที่หายจริงยังหยุดก่อนสร้างหรือเขียนข้อมูล ทดสอบ plugin ผ่าน 184 tests / 850 assertions; reviewer รันซ้ำและไม่พบข้อที่ต้องแก้

UI จริงหลังปิด/เปิดเฉพาะ plugin: ระบุ attachment_6 และ attachment_7 ถูกต้อง เมื่อกดวางที่ D13 ยังหยุดอย่างปลอดภัย [หลักฐาน](../evidence/missing-anchor-diagnostic.png) ยังไม่ได้ซ่อมตำแหน่งสองช่อง เพราะผู้ใช้ยังไม่ระบุตำแหน่งที่ต้องการ

ผู้ใช้ถามว่าถ้ามีช่องจริงทำไมปุ่มไม่แสดง: อธิบายว่ามีเฉพาะ metadata ในฐานข้อมูล แต่ native anchor/OLE ไม่อยู่ใน XLSX ที่เปิด การแก้รอบนี้ไม่ใช่การทำ metadata และเอกสารให้บันทึกพร้อมกัน

ตรวจแนวทางป้องกันแล้ว: SaveTemplate เดิมบันทึกทั้ง workbook และ remount editor จึงไม่ควรแอบเรียกจากปุ่มวาง การปรับเป็นวางพร้อมบันทึกและให้เลือกไฟล์เมื่อยืนยัน artifact สำเร็จต้องแสดงผลการบันทึกชัดเจนและรักษา pending guard ส่วนการรับประกันไม่เกิดข้อมูลค้างทุกกรณีต้องออกแบบ staging/commit ของ binding และ artifact ร่วมกัน ยังไม่ได้ทำรอบนี้ คู่มือปรับให้บันทึกต้นแบบก่อนทดลองเลือกไฟล์
