## Decision: plugin-local Apply, durable Operation at capture

| Choice | Placement proof and auto-save | Recovery and cost for 05 |
| --- | --- | --- |
| Plugin-local working candidate until Save (selected) | Changes to native geometry, controls and field configuration stay together in the live opening. Existing auto-save calls the same explicit capture/commit path as toolbar Save. A saved pre-conversion proof still requires saved bytes; a local candidate never substitutes for it. | Apply has no canonical write and therefore no lost network ACK to reconcile. A dispatched Save or Publish has a durable checkpoint. Refresh can recover its outcome, not an unadmitted working candidate. One server admission protocol, no persistent per-Apply lifecycle. |
| Durable opening-scoped pending candidate at every Apply (rejected) | Candidate metadata still does not prove native placement. A closed editor can leave a durable candidate with no usable workbook. Auto-save still needs capture and the same commit transaction. | Requires candidate versioning, Apply-level reconciliation, retention, abandonment, and mixed-version handling. It does not recover native work without persisting bytes too. It adds no required guarantee over a durable Operation at Save. |

An opening can hold a full desired set of Rules with stable binding IDs; the server revalidates and normalizes it against the locked base. Do not accept client-supplied `proof passed`, derived offsets, catalog identity, or native name existence as authoritative. Do not change the meaning of Tag, row/column mapping, or a Storage Template choice. Keep unapplied panel changes separate from applied working changes; do not silently omit either in Save/Publish. A native command timeout or missing rollback ACK can leave the opening uncertain even _without_ a server write. Freeze mutation, verify same-opening native state against the before/after snapshot, or reopen the saved copy and explicitly lose the uncommitted work. Never call an uncertain local application successful.

## Snapshot, identity and transitions

**Committed snapshot** = Template Draft ID, canonical `documentKey`, commit revision (`bindingRevision`, advanced even on workbook-only saves), immutable artifact object key + content hash, complete normalized Draft Field Rules. Null or absent placement is not proof of either intent or loss. Readers select Rules and pointer together and use the selected immutable bytes thereafter; a native cache key is not a revision selector. No early canonical Rules update, no in-place overwrite, no staged fallback for saved delivery.

**Working → admitted:** Open a valid saved base `B`. Apply runs local Rules/placement changes with local rollback; explicit unbound declarations remain incomplete. For Save/Publish, freeze candidate Rules, edit generation and native evidence before capture; do not allow capture-sensitive edits/second mutation during the attempt. Client allocates and retains a unique request checkpoint _before_ dispatch (scope and action only in browser recovery record; no tokens or workbook). Admission binds that checkpoint and immutable request content to Admin actor + Folio session, Form + target Draft, active lease UUID/generation, opening UUID + `documentServerKey`, base `documentKey` + revision and pinned base artifact key/hash, action and protocol version. Resolve and verify signed scope independently of the client; existing enabled-Admin, authorization, session/lease, Form locks and single-active-Operation checks stay in force. Reject mismatched checkpoint reuse, stale base, expired lease, stale capability, different opening, and wrong action. Return admission only, not success.

**Admitted → validated:** Persist the exact candidate and capture correlation on the Operation before dispatching native force-save. Reuse existing signed callback, single-use claim, trusted origin, package checks and XLSX native snapshot collection. Match callback action, canonical identity, opening/native key and claim; delayed/repeated/mismatched callbacks cannot commit another attempt. Compare captured workbook to native evidence and validate directly against frozen candidate: unique stable IDs, correct named ranges/sheets/full merges, supported geometry and nonoverlap, tracked column names/offsets, managed validations/options, markers/controls and intended removals, attachment slot identity and mapping. Preserve safe handling of legacy no-tracking cases without inferring reorder. Validate the final bytes after any compaction/normalization. An unchanged native response alone is insufficient for a placement-changing or uncertain attempt: require capture evidence from this attempt/opening, or prove the exact committed bytes satisfy the unchanged workbook case. Never substitute a different opening's failed capture or silently fall back to old bytes. Ticket 07 owns generic unchanged-retry behavior; these checks apply specifically to 05.

For sheet validation generated by Field Rules, the final Draft artifact is rebuilt from the frozen Rules using the existing workbook validation writer after verifying placement. This does not trust unsupported native validation or change layout, ordinary cell values, or the conditions for Publish. The writer rejects unsafe overlap with custom formulas rather than rewriting their origin.

**Validated → committed:** Write final validated bytes to a new immutable key with a recorded cleanup intent (record allocated keys durably before writing). Inside one DB transaction recheck Form lock, Admin/session/lease/opening authority, active Operation claim, exact base, no publication race and catalog rules; atomically replace Rules, update object pointer/hash/key/revision, and record Operation completion and resulting identity. The DB commit is the only Save success point. No distributed transaction is needed. Publish consumes the current frozen working pair, not just the last saved one. Its transaction freezes final bytes plus immutable Manifest, Prefill configuration and Published Template, advances Form status/version, and completes the Operation. As in the current publication transaction, keep the last committed Template Draft separate; Publish is not an implicit Save. A failed Publish leaves both the Draft and Form publication state unchanged. Cleanup cannot undo commit; retire only objects proved unreferenced by current/pinned reads or eligible Operations. Failed storage write/callback/transaction, expired or superseded lease, and stale base leave the old canonical pair intact unless original completion proves otherwise. Never restore `B` over a later commit. Storage crash or lost completion may leave an orphan to reconcile, not a pointer readers can access prematurely.

**Incomplete ≠ broken:** Draft Save accepts intentionally unbound or incomplete configuration allowed by existing Draft Rules (e.g. new unplaced table, unfinished attachment configuration); record intentional unbound explicitly in the candidate, with no contradictory managed placement in final bytes. An established binding with a missing/duplicate/moved-to-wrong-slot anchor, tracked column ambiguity, missing button/marker or conflicting validation is broken, not unbound. Clearing a claimed anchor to mask loss is invalid. Intentional removal/unbinding where already supported must be a distinct verified user action and reconcile the workbook; never infer intent from `null` or an absent range. A metadata-only fast path is not required in 05. If used, require server proof of unchanged native edit generation and identical workbook-dependent projection on exact verified base bytes, with the same commit fence; unknown or changed geometry, validation, Tag-to-marker, attachment controls or native edits requires normal capture. Form title/description are outside the paired authoring contract.

**Publish rules unchanged:** Run the current full validators on the resulting pair: complete Spreadsheet Contract, placements, merges/overlaps, types, required options/prefill and configured existing controls, current Storage Template mappings locked in the local catalog, and exactly one noncomputed scalar root `docs_number` when applicable. No new `fiscal_year`, template-entered values or live category-provider recheck. Broken or incomplete placement cannot publish. Keep published structure immutable and PDMS saved-name policy unchanged.

## Exit, reconnect and settlement

- **Exit / discard before dispatch:** Stay, explicitly discard local work, or Save and exit only after confirmed completion. Discard drops the opening state, not the last committed Draft and not any Response/history. Reload/close may lose local work despite browser warnings. Native cache of another opening is not recovery. Same-opening reconnection may retain Rules and native state only after their scope/base and native state are reverified; expired/replaced lease or different session/opening cannot authorize old captures. Renewal cannot silently rebase stale work.
- **Unknown after dispatch:** A lost 202, callback response, polling response or success ACK is not failure. Persist checkpoint and original action until bounded reconciliation. Query the exact original checkpoint under authorized Form/actor/session recovery; return durable pending/processing/completed/failed, original resulting tuple when completed, and current canonical tuple separately. Completion of the original is not receipt for later edits. Unauthorized sessions cannot adopt a checkpoint or borrow an editor lease. After reauthentication, re-establish permitted status-read access, not mutation authority from the ended session. Pending/processing or unproved outcomes block redispatch and cannot be discarded into an apparent rollback; saved-copy access remains available.
- **No original row found:** Not settlement. A recovery operation may report not admitted only after atomically fencing the original admission lease/generation under the same locks used by admission. Return the original record if admission already won. A terminal rejection/failure must also fence its outstanding claims against future commit. No replay, no elapsed-time assumption. Only after terminal proof may the user explicitly initiate a different request with a new checkpoint, valid lease, verified editor state and current base. If `B` is no longer current, reopen or deliberately reapply; do not auto-merge stale working changes.
- **Rollback:** Before admission, restore only same-opening native state with positive verification. After admission failure/abort, keep canonical pair untouched; same-opening local work may remain pending if verified, not automatically saved. After confirmed commit, do not undo through recovery; any later editable change starts a fresh operation. Reopen the current committed pair if continuation cannot be proved. No claim that a refresh restores working changes.

## Compatibility and rollout

Read valid legacy pairs without migrating or guessing geometry. Legacy unbound intent must be demonstrated, not inferred; classify ambiguous or already split Drafts as needing repair, preserving saved access and current bytes. The Admin must explicitly verify/rebind or remove conflicting placement before Save/Publish; ticket 06 owns diagnosis/repair tooling, not automatic history changes. Do not treat old same-width layout as identity proof. Existing Published Templates, old PoC behavior, DOCX, Responses and historical artifacts stay unchanged.

Use a version gate on XLSX authoring config and every mutation/capture admission; require new server plus new plugin before enabling edits. Disable old writer nodes and drain/settle old Operations under their own claims before enabling the new protocol for a Form. Old plugin on new server: saved access works, old mutation routes reject with reopen/upgrade guidance. New plugin on old server: no negotiated atomic support, so no XLSX mutation fallback. A cached tab opened before cutover must not be able to PATCH; admission/commit must reject old tokens, claims and protocol once fenced. Do not roll back into a mixed writer pool or restore the split writer. Safe rollback disables XLSX mutations while preserving saved reads and Operation settlement; schema additions must survive rollback where used.
