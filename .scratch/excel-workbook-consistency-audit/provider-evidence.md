## Current source and release boundary

- [Upload boundary](../../apps/server/src/ecm/attachments.ts#L702): Folio records the attempt before sending and processes receipts sequentially. A version already started cannot be sent again. Transport or invalid-response failure leaves a started attempt `unknown`. A validated original `file_token` + `file_link` pair is retained for that attempt, even if the Operation expired. The client [validates a single paired receipt](../../apps/server/src/ecm/client.ts#L604); HTTP 200 alone is not sufficient. Sender fencing stops future Folio dispatch/commit, not an already-dispatched provider mutation.
- [Identity and conflict](../../apps/server/src/ecm/identity.ts#L160): match within the service account by both token and link. Partial, multiple or otherwise unsafe matches fail closed; a repeated filename does not establish identity. Matching protected history can reject a new Folio commit even after a provider write. Distinct pairs are not proof of independent physical storage for every future write.
- [Response completion](../../apps/server/src/operations/response-completion.ts#L152) commits attachment references through the Folio transaction. That transaction does not include the provider's HTTP write. [Original-byte checks](../../apps/server/src/ecm/client.ts#L553) use trusted receipt and size; template reuse requires corroborating SHA-256. Do not infer a historic digest from current bytes or substitute a later revision. No application behavior changed in this ticket.
- Settlement needs provenance for the **exact original mutation**: environment and account scope, original dispatch/request or Operation/attempt correlation, affected resource/paired receipt when available, and a terminal provider record or applicable versioned contract ruling out delayed effects for that request. An original paired success receipt establishes the known received outcome of its own upload. For byte integrity, compare SHA-256 captured from the original input with an authorized read through that exact pair; report observed time and scope. A changed/unchanged digest alone does not settle an unrelated mutation. HTTP status, elapsed time, empty search, same-name matches, sender fence, or an operator note alone do not settle a request. The previously inspected public API collection exposed no documented original-request finality contract; that is not proof that DCM has no other evidence.
