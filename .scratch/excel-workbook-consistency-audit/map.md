## 1. ต้นเหตุและหลักฐาน

**A1 — P1, ยืนยันซ้ำ:** เมื่อกดเพิ่มตารางธรรมดา ปลั๊กอินสร้าง named range ใน editor แล้วส่ง `PATCH spreadsheet-bindings`. ฝั่ง server เพิ่ม `bindingRevision` และแทน `DraftFieldRule` ใน PostgreSQL ทันที แต่ไม่เปลี่ยน `objectKey`. เมื่อเปิดใหม่ Editor Config อ่านกฎล่าสุดกับ workbook เก่า. ปลั๊กอินตรวจช่วงตารางแล้วขึ้น `ไม่พบตำแหน่งตาราง กรุณาผูกตำแหน่งตารางใหม่ก่อนบันทึก`; guard นี้กันการเพิ่มปุ่มและการบันทึกจากช่วงที่ยืนยันไม่ได้ ไม่ใช่ต้นเหตุและไม่ควรถอดออก. ดู [saveBinding](../../apps/onlyoffice-plugin/src/spreadsheet.js#L2036), [PATCH transaction](../../apps/server/src/routes/spreadsheet-authoring.ts#L428), [editor-config](../../apps/server/src/routes/form-authoring.ts#L132), [columns guard](../../apps/onlyoffice-plugin/src/spreadsheet-columns.js#L71), [authoring readiness](../../apps/onlyoffice-plugin/src/spreadsheet.js#L2784)

**A2 — P1, ยืนยันซ้ำ:** ช่องเดี่ยวธรรมดาเกิด split เดียวกัน แต่แจ้ง `มีช่องที่ไม่พบตำแหน่งใน Excel` ไม่ใช่ error ตาราง. ช่องแนบใหม่ก็เกิดได้ถ้า `PATCH` ผ่านแต่ auto-save ถูกปฏิเสธ. การย้ายปุ่มก่อนสร้างตารางในแพตช์เดิมแก้ mapping/projection ในเส้นทางปกติและสั่ง auto-save แต่ยังคง `PATCH` ก่อน Save. ความเสี่ยงเดียวกันใน promotion เป็นข้อสรุปจากลำดับ source ยังไม่ได้ fault-inject promotion โดยตรง. ดู [one-click attachment](../../apps/onlyoffice-plugin/src/spreadsheet.js#L1923), [placement proof/auto-save](../../apps/onlyoffice-plugin/src/spreadsheet.js#L2006), [promotion commit + save](../../apps/onlyoffice-plugin/src/spreadsheet.js#L2309)

**A3 — P1, ยืนยันซ้ำสำหรับ ACK loss; เกณฑ์ Save ยืนยันจาก integration test:** เมื่อ `PATCH` commit แต่ตอบกลับล้ม, GET ยืนยันกฎได้และ editor เดิมยังใช้ต่อได้ แต่ไม่ได้พิสูจน์ว่า canonical workbook มี range ใหม่. `/recover` ใช้ revision/lease/fence กัน delayed PATCH และตรวจ native snapshot ใน editor เดิม ไม่ได้ยืนยัน canonical file. ส่วน Save ตรวจ snapshot ของ named ranges เทียบ bytes; `null` ตรงกับไม่มีชื่ออาจผ่านได้ตามสัญญา incomplete Draft. HTTP test ปัจจุบันจงใจยืนยันว่า incomplete table ที่ยังไม่มี anchor บันทึกได้; Publish ตรวจเข้มกว่า. ต้องแยก **ตั้งใจยังไม่ผูก** ออกจาก **เคยผูกแล้วแต่ไฟล์ไม่ตรง** ไม่ใช่ห้ามบันทึกทุก incomplete Draft. ดู [plugin recovery](../../apps/onlyoffice-plugin/src/spreadsheet.js#L1356), [server recovery](../../apps/server/src/routes/spreadsheet-authoring.ts#L483), [snapshot comparison](../../apps/server/src/documents/spreadsheets/save-snapshot.ts#L25), [incomplete-draft contract test](../../apps/server/test/http/spreadsheet-authoring.test.ts#L696)

### Red-capable loop และ controls

รันใน detached sandbox checkout โดยใช้ production plugin bundle และ ONLYOFFICE API/transport fixture. Script ชั่วคราวถูกลบหลังตรวจ. ตัดปุ่มแนบ, header, ECM และข้อมูลจริงออก เหลือตาราง 1 คอลัมน์ 2 แถว `A1:A2`: รอข้อความว่าตั้งค่าสำเร็จ เปิดกลับด้วย canonical names แล้วกดเพิ่มปุ่ม. ตรวจพบ error ซ้ำ 2 รอบ; ตัด PATCH แล้วไม่พบ error

```text
bun apps/onlyoffice-plugin/test/.audit-excel-reopen.js
before reopen: kind=table revision=1 workbook_saves=0 live_anchor=true committed_anchor=false
reopen: ไม่พบตำแหน่งตาราง กรุณาผูกตำแหน่งตารางใหม่ก่อนบันทึก
exit 1
```

| Control / fault | สิ่งที่สังเกตได้ |
| --- | --- |
| `CONTROL=no-patch` | revision 0, ไม่มี missing-anchor warning, exit 0 |
| `CONTROL=saved` | revision 1, Save 1 ครั้ง, canonical anchor มี, เปิดใหม่ไม่เตือน, exit 0 |
| `CASE=field` | revision 1, Save 0, เปิดใหม่เตือนช่องเดี่ยวไม่มีตำแหน่ง, exit 1 |
| `CASE=attachment` | auto-save สำเร็จ 1 ครั้ง, canonical anchor มี, exit 0 |
| `CASE=attachment CONTROL=save-fails` | PATCH สำเร็จ; Save ถูก fixture ปฏิเสธ 503; เปิดใหม่เตือนตำแหน่งช่องแนบหาย, exit 1 |
| `CONTROL=lost-patch-ack` | PATCH commit แต่ตอบ 503; GET ยืนยัน metadata สำเร็จใน editor เดิม; เปิดใหม่ยังเจอ missing table, exit 1 |

ฝั่ง server รัน HTTP fixture กับ PostgreSQL/RustFS แยก ใช้ Admin และ Form สังเคราะห์: `bun --no-env-file test --timeout 30000 test/http/.audit-excel-history.test.ts -t 'audit invariant: table PATCH'` คาดหวังให้กฎที่อ่านได้มี anchor ในไฟล์เดิม, วัด `PATCH=200; reopened revision=1; stored workbook contains table anchor=false` (exit 1). Existing `test/http/spreadsheet-authoring.test.ts`: **9 ผ่าน / 167 assertions** ที่รวม incomplete Draft, stale save rejection, publication และ selected-history controls. ไม่มีผลทดสอบ browser/native เต็มรอบใหม่ในรอบ audit นี้

## 4. แผนแก้ตามลำดับ

1. **P1: เปลี่ยนหน่วย commit ของ XLSX Template Draft ไม่ใช่เพิ่ม auto-save ทีละปุ่ม.** ให้ field mutation ทั้งหมดเป็น working changes หรือ durable pending Operation ที่ผูก `form + lease + opening + base revision` จนมี workbook snapshot ที่ยืนยันได้. สร้าง/ตรวจ artifact ใน storage ที่ยังไม่เปิดให้ canonical reader. ภายใต้ lock/compare-and-swap ภายใน DB transaction เดียว เปลี่ยนชุด bindings + artifact pointer/hash + revision + Operation completed. เก็บคู่เดิมอ่านได้จนกว่าคู่ใหม่ commit; จัดการ orphan ผ่าน cleanup intent. ไม่ต้องทำ distributed transaction ระหว่าง PostgreSQL กับ object store ถ้าเขียน object แบบ immutable ก่อน และ publish pointer เฉพาะใน DB transaction. ใช้ machinery ของ Operation/lease/callback ที่มีอยู่; อย่าลด scope proof เพื่อให้เทสต์ผ่าน
2. **กำหนดความหมายของ Draft ที่ยังไม่ครบและ unknown outcome.** อนุญาต metadata ที่ตั้งใจยังไม่ผูก แต่ห้ามถือ field ที่อ้างว่าผูกแล้วว่า valid ถ้า workbook ไม่ตรง. Save metadata-only ทำได้เฉพาะเมื่อพิสูจน์ว่า native contract ไม่เปลี่ยน. Recovery ต้องระบุ original operation และคู่ล่าสุดที่ commit แยกจาก pending; เปลี่ยนแท็บ/refresh/discard ต้องอ่านคู่เดียวกันเสมอ. เปลี่ยนข้อความ UI เป็น “ตั้งค่าในตัวแก้ไขแล้ว ยังไม่ได้บันทึกต้นแบบ” จนคู่ใหม่สำเร็จ; UI warning ไม่ใช่ root fix
3. **P1 แยกทำขนาน:** แก้ R1 ด้วย pinned Submission/revision, R2 ด้วย committed-only document delivery และ regression วัด bytes, R3 ด้วย policy ทิ้งร่างแบบรักษาประวัติและการยืนยันขอบเขตการลบ. ไม่รวมสามเรื่องนี้เป็น rewrite ของ attachment pipeline
4. **ซ่อมร่างเก่าอย่างปลอดภัย:** ออกแบบ read-only inventory หาตาราง/name/marker/validation ไม่ตรงโดยจำแนก _ตั้งใจไม่ครบ / ขาดชื่อ / ซ้ำ / proof ไม่พอ_. ห้าม auto-bind จาก Tag/offset/ตำแหน่งปุ่มอย่างเดียว. ให้ Admin ดู/ดาวน์โหลดคู่เดิม เลือกช่วงหรือ revert ไปยัง revision ที่พิสูจน์ได้ ถ้าไม่มีหลักฐานแสดง actionable repair ห้ามแก้ Published Template/Submission/Correction ย้อนหลัง. งาน inventory กับข้อมูลจริงแยกขออนุญาต
5. **หลัง core fix:** ปิด R4/R6 ด้วย tests ก่อนแก้. ตรวจ R5/R7–R10 ตาม policy/fixture และหลักฐานแยก; ไม่สรุป provider-wide acceptance จาก mock, `200`, หรือ ticket closure

### เกณฑ์รับงานครั้งถัดไป

- **Admin authoring:** scalar/table/column/picture/dropdown/PDMS/attachment promote/convert/delete/rebind; หลังแต่ละขั้น inject stop ก่อน/หลัง metadata preparation, storage write, callback, DB commit และ ACK. เปิดใหม่ใน opening ใหม่และ lease เดิม/หมดอายุ; ต้องเห็นคู่เก่าหรือคู่ใหม่เต็มชุดเท่านั้น. Case “intentional incomplete” Save ได้แต่ Publish ไม่ได้. รันทดสอบสอง admin, stale tab, undo, inserted/hidden rows/cols แล้ว test duplicate/export ว่าอ่านคู่ที่ pin
- **User/Correction:** ถอด capture retry, repeat/callback delay, reconnect, reopen/resubmit, late File/removal; assert canonical XLSX และ JSON/refs ชุดเดียวกัน, rowIndex ตามตำแหน่งจริง, ไม่มี upload จาก internal operation, ประวัติเดิมไม่เปลี่ยน. DCM unknown/outcome test เริ่มที่ loopback และตรวจ original checkpoint เท่านั้น
- **Read-only/cleanup:** สอง Submission และสอง revision ที่มีต่าง workbook hashes; preview, Fields, JSON, XLSX, PDF อ้างคู่เดียวกัน; ทดสอบ authenticated Admin/Viewer/owner/foreign cases. ขณะ worker active ต้องไม่เห็น staged bytes. Dashboard ทิ้งร่างหลังเคยส่งต้องไม่แตะ Submission/Correction เว้นแต่ผู้ใช้ยืนยัน whole-Response delete ตาม policy. PDF fail แยกจาก persistence; cleanup fail แยกจาก commit
- **หลักฐานย้อนหลัง:** รายงาน [local/native/HTTP และ provider follow-up](../ecm-attachment-safety-implementation/acceptance-report.md) เก็บตาม scope เดิม. Findings R3–R10 ยังไม่ใช่ข้อสรุปจากการทดสอบ native/production รอบนี้. ไม่มี code change, commit, push, deploy, real account access หรือคำขอ DCM/PDMS จริงใน audit นี้
