# ข้อกำหนดชนิดไฟล์และขนาดที่รับได้

Labels: wayfinder:grilling Type: grilling Parent: ../map.md Status: resolved Assignee: pyw1tt Blocked by: 01, 09

## Question

ภายใต้ข้อกำหนดล่าสุดที่รับไฟล์ทุกชนิดแต่หนึ่งไฟล์ต่อช่อง จะกำหนดขนาดสูงสุด ไฟล์ว่าง ไฟล์เข้ารหัส และวิธีเปิด/ดาวน์โหลดไฟล์ที่อาจมี active content อย่างไรให้เหมาะกับการใช้งานและข้อจำกัด ECM? ช่องแนบบังคับหรือไม่ และ Save Draft ต่างจาก Submit อย่างไร?

ไม่จำกัดนามสกุลเป็น PDF และไม่แปลงเนื้อหาหรือเปลี่ยนนามสกุลทุกไฟล์เป็น `.pdf` การตรวจสิทธิ์ ปลายทาง จำนวนไฟล์ ขนาด และความปลอดภัยของชื่อ/การจัดการเนื้อหาฝั่ง server ยังคงจำเป็น ตัดสินเกณฑ์ที่ผู้ใช้ต้องรับรู้และข้อความที่แก้ไขต่อได้ โดยไม่เพิ่ม allowlist ชนิดไฟล์ที่ขัดกับข้อกำหนดล่าสุดโดยเงียบ ๆ

เริ่มหารือเพดานขนาด ไฟล์ว่าง/เข้ารหัส ความจำเป็นของช่องแนบ และวิธีเปิดหรือดาวน์โหลด โดยยึดข้อกำหนดรับไฟล์ทุกชนิดหนึ่งไฟล์ต่อช่อง ไม่กลับไปกำหนด PDF-only และไม่แก้กติกาชื่อไฟล์ที่ยืนยันแล้ว ขอบเขตเป็นการวางแผน ไม่แก้ application หรือเรียก ECM จริง

### Discussion — 2026-11-12 — เกณฑ์รับไฟล์รอบแรก

- ผู้ใช้กำหนดเพดาน Folio ที่ 10 MB ต่อไฟล์ หมายถึง 10,000,000 bytes ของไฟล์ ไม่ใช่ 10 MiB และไม่ใช่ multipart body ทั้งคำขอ ขอบเขตนี้เป็น product limit ไม่ใช่ผลทดสอบเพดานของ ECM
- รับไฟล์ขนาด 0 bytes ได้ ไม่เพิ่มข้อกำหนดว่าไฟล์ต้องมีเนื้อหา แต่ยังต้องตกลงว่าไฟล์ว่างนับผ่าน required หรือไม่
- รับไฟล์ที่มีรหัสผ่านได้โดย Folio ไม่ขอรหัส ไม่ถอดรหัสและไม่อ้างว่าเปิดหรือตรวจเนื้อหาภายในได้ การรับไฟล์นี้เป็นข้อกำหนด Folio ไม่ใช่หลักฐานว่า ECM รับทุกชนิดสำเร็จจริง
- Admin กำหนด required รายช่องแนบหรือคอลัมน์ได้ Draft ยังบันทึกแบบไม่แนบในช่องบังคับได้ แต่ Submit ต้องแนบครบ ไฟล์ที่เลือกแล้วแต่ไม่ผ่านเกณฑ์ต้องแก้ ไม่ข้าม validation เพราะเป็น Draft
- ดาวน์โหลดไฟล์แนบอย่างเดียว ไม่สร้าง preview หรือ render เนื้อหาไฟล์แนบในหน้า Folio ข้อนี้ไม่ทำให้ URL public ต้นทางมีสิทธิ์ควบคุมหรือรับรองว่าไฟล์ปลอดภัย

หลักฐานประกอบคำถามเรื่องแถว: `extractSpreadsheetData` ใน [workbook.ts](../../../apps/server/src/documents/spreadsheets/workbook.ts) lines 577–608 นับแถวจากค่าของ input columns ที่ไม่ว่าง ไม่ได้ข้ามแถวโดยดูจำนวนปุ่ม ปัจจุบันไฟล์แนบยังเป็น PoC จึงไม่ใช้พฤติกรรมนี้เป็นหลักฐานว่าระบบนับแถวที่มีแต่ไฟล์แนบได้แล้ว ต้องกำหนดความหมายแถวสำหรับ validation ไฟล์แนบให้ชัดก่อนสรุป

### Discussion — 2026-11-12 — ไฟล์ว่างและขอบเขตแถว

- ผู้ใช้ยืนยันว่าไฟล์ 0 bytes ที่อัปโหลดและบันทึกสำเร็จนับว่าช่อง required แนบครบ การตรวจนี้หมายถึงมีไฟล์ ไม่ใช่การรับรองเนื้อหา ชื่อไฟล์อย่างเดียวหรือ File ที่ยังเลือกค้างไว้ไม่ถือว่าแนบสำเร็จ
- คอลัมน์แนบที่บังคับตรวจเฉพาะแถวที่มีข้อมูลกรอกหรือมีไฟล์แนบอย่างน้อยหนึ่งช่อง ไม่บังคับแถวว่างทั้งหมด
- แถวที่มีแต่ไฟล์แนบต้องคงเป็นแถวคำตอบ แม้ไฟล์นั้นเป็น 0 bytes และต้องตรวจคอลัมน์แนบ required อื่นในแถวนั้นก่อน Submit ไม่ใช้การไม่มีค่า cell เป็นเหตุทิ้งไฟล์หรือข้าม required

รายละเอียดการนำไฟล์แนบมารวมกับการอ่านข้อมูลตารางต้องทำจริงในขั้นพัฒนา ปัจจุบันเป็นข้อกำหนดที่ตัดสินผ่านการสนทนา ยังไม่ใช่ผลทดสอบว่า PoC ทำได้แล้ว

### Resolution — 2026-11-12 — ยืนยันร่วมกับผู้ใช้

ผู้ใช้ยืนยันเกณฑ์รับไฟล์ ขอบเขต required และวิธีดาวน์โหลดแล้ว ข้อสรุปนี้แทนสถานะที่ยังรอตัดสินใน Discussion ก่อนหน้า ใช้กับไฟล์แนบ ไม่เปลี่ยน viewer หรือการตรวจเอกสาร Form หลัก และไม่อนุญาตให้แก้ application หรือเรียก ECM จริง

#### ชนิด จำนวน และขนาด

- รับไฟล์ทุกชนิด หนึ่งไฟล์ต่อช่อง ไม่เพิ่ม allowlist นามสกุลหรือบังคับว่าเป็น PDF ไม่แปลงเนื้อหาและไม่เปลี่ยนนามสกุลเพื่อให้ดูเหมือนชนิดอื่น
- ขนาดที่ยอมรับใน Folio คือ `0 <= bytes <= 10,000,000` ต่อไฟล์ รวมไฟล์ที่มีขนาดตรงเพดาน ไม่ใช่ 10 MiB และไม่ใช่เพดานรวม multipart body หรือไฟล์ทุกช่องในคำตอบ
- ตรวจขนาดจริงฝั่ง server ด้วย ไม่เชื่อเฉพาะชื่อไฟล์ MIME ที่ client แจ้ง หรือค่า `Content-Length` จาก client และไม่ลดการตรวจสิทธิ์/ปลายทางเพราะยอมรับทุกชนิด
- รับไฟล์ 0 bytes ได้ ต้องแยก “มีไฟล์ที่ขนาดเป็นศูนย์” ออกจาก “ยังไม่มีไฟล์” ไม่เติมเนื้อหาปลอมเพื่อให้ขนาดมากกว่าศูนย์
- รับไฟล์มีรหัสผ่านโดยไม่ขอรหัส ไม่ถอดรหัสและไม่ประมวลผลเนื้อหาใน Folio ไม่อ้างว่าไฟล์เปิดได้ ไม่เสียหาย หรือปลอดภัยจากการที่อัปโหลดผ่าน
- กติกาชื่อไฟล์/อักขระและ metadata ยังคงตาม [แหล่งเลขที่หนังสือยืนยันและกติกาชื่อไฟล์](04-confirmation-filename.md) การรับไฟล์ทุกชนิดไม่ได้ยกเลิกกฎเหล่านั้น

#### ช่องบังคับและ Draft/Submit

- Admin กำหนด required รายช่องแนบเดี่ยวหรือคอลัมน์ตาราง โดยเป็นส่วนหนึ่งของสัญญาฟอร์มตาม [ระดับการตั้งค่าปลายทางไฟล์ของ Admin](03-admin-storage-policy.md)
- Draft บันทึกได้แม้ยังไม่มีไฟล์ในช่อง required แต่ก่อน Submit ต้องมีไฟล์ที่บันทึกสำเร็จจริงในช่อง required ที่เกี่ยวข้อง ไม่ถือว่าชื่อไฟล์หรือตัวเลือก File ใน browser อย่างเดียวเป็นการแนบสำเร็จ
- ไฟล์ 0 bytes ที่อัปโหลดและบันทึกสำเร็จนับผ่าน required เช่นเดียวกับไฟล์ขนาดอื่น required หมายถึงมีไฟล์ ไม่ใช่การตรวจคุณภาพหรือเนื้อหา
- ไฟล์ที่เลือกแล้วแต่ไม่ผ่านเกณฑ์ต้องแก้ ไม่ข้ามการตรวจเพราะเป็น Draft และไม่รายงานว่าบันทึกไฟล์สำเร็จเพียงเพราะข้อมูลคำตอบส่วนอื่นบันทึกได้

#### แถวตารางที่เกี่ยวข้อง

- ตรวจคอลัมน์แนบ required เฉพาะแถวที่มีข้อมูลกรอกหรือมีไฟล์แนบอย่างน้อยหนึ่งช่อง แถวที่ว่างทั้งหมดไม่มีไฟล์ไม่ต้องแนบเพียงเพราะมีปุ่ม
- แถวที่มีแต่ไฟล์แนบเป็นแถวคำตอบ ต้องไม่ถูกทิ้งเพราะไม่มีค่าใน cell อื่น รวมกรณีแนบไฟล์ 0 bytes และต้องตรวจคอลัมน์ required อื่นของแถวนั้นก่อน Submit
- การมีไฟล์เลือกค้างไว้อาจทำให้แถวนั้นเป็นแถวที่ต้องจัดการ แต่ยังไม่ทำให้ required ผ่านจนไฟล์ถูกบันทึกสำเร็จจริง วิธีรวมแถว/ตัวอ้างอิงไฟล์และลำดับตรวจอยู่ในหัวข้อวงจรไฟล์ ไม่ใช้การทิ้งแถวเพื่อหลบ validation

#### การเปิดไฟล์และการแจ้งปัญหา

- วิธีแสดงและเปิดไฟล์หลังบันทึกให้ยึด [ข้อกำหนด URL ล่าสุด](06-history-access.md): ผู้ใช้เปลี่ยนจากดาวน์โหลดอย่างเดียวเป็นแสดง URL ต้นทางในหน้าดูและ export เพื่อเปิดเอกสาร ไม่สร้าง preview ที่ฝังเนื้อหาใน Folio และไม่ขอรหัสผ่านเพื่อถอดไฟล์
- ข้อนี้ไม่ลบหรือเปลี่ยน viewer ของ DOCX/XLSX หลัก ไม่ตัดสินสิทธิ์ User/Admin/Viewer และไม่ทำให้ URL public ของ ECM กลายเป็น private
- เมื่อไฟล์ไม่ผ่านเกณฑ์หรือ ECM ปฏิเสธ ให้แจ้งช่องและแถวที่มีปัญหา พร้อมสาเหตุที่แก้ไขต่อได้ เช่น ขนาดจริงกับเพดาน โดยไม่ส่ง credentials/token หรือ raw upstream errors กลับผู้ใช้
- การเลือกไฟล์ทดแทนที่ไม่ผ่านเกณฑ์หรือการอัปโหลดที่ล้มเหลวต้องไม่ทำให้ไฟล์เดิมสูญหาย ลำดับเก็บ/ลบและผลสำเร็จบางช่องเป็นของ [วงจรไฟล์ร่างและการบันทึกโดยไม่สูญหาย](05-safe-draft-lifecycle.md)

#### หลักฐานและขอบเขตที่ยังเปิด

- ตรวจ source ของ `extractSpreadsheetData` แล้วพบว่าการอ่านแถวเดิมอาศัยค่า input cells; ข้อกำหนดแถวที่มีแต่ไฟล์แนบเป็นพฤติกรรมที่ต้องพัฒนาและตรวจจริง ไม่ได้มีหลักฐานว่า PoC ทำได้แล้ว
- `10,000,000 bytes`, ไฟล์ว่าง และไฟล์มีรหัสผ่านเป็นเกณฑ์ที่ผู้ใช้กำหนดให้ Folio ไม่ใช่ผลทดสอบว่า ECM/proxy รับได้ทั้งหมด หาก ECM ปฏิเสธต้องแจ้งตามจริง ไม่ขยายขนาด เปลี่ยนไฟล์ หรืออ้างผลสำเร็จเอง
- [สิทธิ์ไฟล์และการแก้ไขหลังส่งคำตอบ](06-history-access.md), [การใช้บัญชี ECM ร่วมโดยไม่ตัด token ของระบบอื่น](10-shared-ecm-login.md) และหัวข้อวงจรไฟล์ยังเปิดตาม dependencies เดิม

ไม่ได้ทดลอง upload/download/delete หรือ login ECM จริง ไม่แก้ application/DB ไม่เปลี่ยน ADR และไม่สร้างการสแกนมัลแวร์หรือรับรองความปลอดภัยของเนื้อหาโดยไม่มีหลักฐาน
