# การเปลี่ยนฟอร์ม PoC เดิมไปใช้ช่องแนบจริง

Labels: wayfinder:grilling Type: grilling Parent: ../map.md Status: resolved Assignee: pyw1tt Blocked by: 03, 06, 11

## Question

เมื่อช่องแนบจริงใช้ object ใน JSON แทน PoC ที่เป็น text Field และเก็บ File เฉพาะใน browser ฟอร์มและคำตอบ PoC ที่มีอยู่จะเริ่มใช้ความสามารถใหม่อย่างไร โดยไม่แก้สัญญาของ Published Template ย้อนหลัง ไม่ทำข้อมูลเดิมหาย และไม่อ้างว่าชื่อไฟล์หรือ URL ที่กรอกเองเป็นไฟล์ที่อัปโหลดแล้ว?

ต้องตัดสินนโยบายสำหรับ:

- Template Draft ที่มีปุ่ม PoC และ binding/tag เดิม: Admin ต้องตรวจหรือตั้งค่าอะไรเพิ่มก่อนเผยแพร่ให้เป็นช่องแนบจริง และจะรักษาการผูกช่องเดิมอย่างไร
- Published Form ที่มี PoC: การใช้ความสามารถใหม่ต้องสอดคล้องกับกติกา Published Template ที่แก้โครงสร้างไม่ได้และเปลี่ยนผ่านการทำสำเนา Form ให้ระบุว่าฟอร์มเดิมยังใช้งานส่วนใดได้ และจะสื่อสาร/พาผู้ใช้ไปทำอะไรต่อ ไม่ตัดสินให้เปลี่ยน manifest ของฟอร์มเดิมโดยอัตโนมัติ
- Draft/Submission/Correction ของฟอร์มเดิมที่ไม่มี canonical file object: การอ่านประวัติและดำเนินงานต่อจะทำอย่างไร โดยไม่แปลง string เป็นหลักฐาน upload ไม่สร้าง file token ปลอม และไม่ย้ายข้อมูลหรือไฟล์ข้าม Form โดยถือว่าผู้ใช้อนุมัติแล้ว
- File ที่เลือกค้างใน browser ตอนเปลี่ยนผ่าน แต่ยังไม่บันทึกจริง: ผู้ใช้ต้องทำอะไรต่อและต้องได้รับคำเตือนอย่างไร ไม่รับรองว่าสามารถกู้ไฟล์จากชื่อที่บันทึกไว้ได้

หัวข้อนี้เลือกนโยบายเปลี่ยนผ่านและสิ่งที่ผู้ใช้ต้องทำ ไม่ทำ migration ไม่แก้ข้อมูลจริง และไม่กำหนดลำดับ upload/save/delete แทนหัวข้อวงจรไฟล์ร่าง

## Comments

### Current behavior — 2026-11-13 — หลักฐานก่อนหารือ

- `automaticUploadPocField` สร้าง `attachment_N` โดยผูก stable binding และกำหนดชนิดเป็น `text` ไม่ใช่สัญญา file object ที่เพิ่งยืนยันใน [สัญญา JSON ของไฟล์แนบและ URL ใน Excel](11-attachment-json-contract.md)
- `UploadPocPendingFiles` เก็บ `File` ใน Map ของ instance เท่านั้น มี guard ปฏิเสธ Save Draft/Submit เมื่อมีไฟล์เลือกค้าง และล้างไฟล์เมื่อ scope เปลี่ยน ชื่อไฟล์อย่างเดียวไม่ทำให้เรียกคืน bytes ได้
- ทดลองเรียกคลาสจริงด้วย `File` สังเคราะห์ชื่อ `poc-memory-only.txt` ขนาด 24 bytes: เลือกได้และ `hasPending` เป็น true; `pending-file-check` ของ Save Draft ปฏิเสธด้วยข้อความว่ายังไม่อัปโหลดหรือบันทึกถาวร; เมื่อสร้าง host instance ใหม่หรือเปลี่ยน document scope ได้ `filename: null`, `hasPending: false`, `size: null` ตามคาด ไม่มีการเปิด UI, เรียก DB หรือ ECM และไม่มี permanent test เพิ่ม
- อ่านเส้นทางทำสำเนาใน `form-catalog.ts`: สร้าง Form/Template Draft ใหม่จากเอกสารและ Field rules ของต้นทาง ไม่ได้คัดลอกคำตอบเก่าไปเป็น Response ของ Form ใหม่ ไม่ได้เรียกเส้นทางนี้จริงกับ DB
- `CONTEXT.md` กำหนด Published Template เป็นสัญญาที่เปลี่ยนโครงสร้างย้อนหลังไม่ได้ การใช้ contract ใหม่กับ Form ที่เผยแพร่แล้วจึงต้องสอดคล้องกับวิธีทำสำเนา ไม่ลด validation หรือสร้าง URL/token ให้ข้อมูลเก่า

### Intended behavior ที่ยืนยันแล้วและขอบเขตการหารือ

สัญญาไฟล์แนบจริง การเลือก category โดย Admin และการเก็บประวัติให้ยึด prerequisite tickets ไม่เปิดการตัดสินใจเหล่านั้นซ้ำ หัวข้อนี้ยังไม่ยืนยันว่าจะนำปุ่ม PoC ใน Template Draft ไปต่ออย่างไร หรือจะเปิดรับข้อมูลทั่วไปจาก Form PoC เก่าต่อหรือไม่

เสนอให้รักษาคำตอบ/ประวัติเดิม ไม่ย้ายคำตอบหรือ File ที่เลือกค้างข้าม Form อัตโนมัติ ไม่ตีความ string เป็นไฟล์ที่อัปโหลด และเตือนผู้ใช้ว่าต้องเลือกไฟล์ใหม่เมื่อเปิด scope ใหม่ ส่วนการรับข้อมูลทั่วไปจาก Form เก่าเทียบกับการให้ Admin archive หลังมีฉบับใหม่ เป็นนโยบายที่รอผู้ใช้เลือก ไม่ใช่พฤติกรรมที่เปลี่ยนแล้ว

ยังไม่ปิดตั๋ว ไม่ดำเนิน migration ไม่แก้ source/config/ข้อมูลจริง และไม่เลือกวิธี ECM login แทนหัวข้อที่รอทีม

### Resolution — 2026-11-13 — ยืนยันร่วมกับผู้ใช้

ผู้ใช้เลือก **“ใช้ช่องเดิม แล้วให้ Admin ตั้งค่า”** สำหรับ Template Draft และ **“คงรับข้อมูลทั่วไปจากฟอร์มเดิม”** สำหรับ Form PoC ที่เผยแพร่แล้ว ไม่เลือกสร้างช่องใหม่ทั้งหมดเป็นข้อบังคับ และไม่เลือก archive ฟอร์มเก่าเป็นส่วนหนึ่งของการเปลี่ยนผ่าน

#### Template Draft และสำเนาที่จะเผยแพร่ใหม่

- Admin ใช้ตำแหน่งและ tag เดิมได้ โดยรักษา stable binding ที่ตรวจสอบได้ แล้วตั้งค่าช่องแนบจริงอย่างชัดเจนผ่านการตั้งค่าต้นแบบ ไม่แปลงปุ่ม PoC หรือ text Fields ทั้งระบบอัตโนมัติ
- ตรวจว่าเป็นปุ่ม PoC/ช่องที่ Admin ตั้งใจปรับจริงจาก binding และหลักฐานตำแหน่ง ไม่เดาจากชื่อ `attachment_N` หรือชื่อ label เพียงอย่างเดียว หาก mapping ไม่ชัดเจนหรือค่าเดิมขัดกับสัญญาใหม่ ให้แจ้ง Admin และรักษาข้อมูลเดิมไว้จนแก้ไข ไม่เลือกช่องข้างเคียงหรือล้างค่าเงียบ ๆ
- ก่อนเผยแพร่ Admin ต้องเลือก category และตรวจ scalar tags `fiscal_year`/`docs_number` ตาม [ระดับการตั้งค่าปลายทางไฟล์ของ Admin](03-admin-storage-policy.md) และ [แหล่งเลขที่หนังสือยืนยันและกติกาชื่อไฟล์](04-confirmation-filename.md) ไม่ใส่ปีหรือเลขหนังสือของ User ให้เองเพียงเพื่อให้ต้นแบบเผยแพร่ผ่าน
- Template Draft ที่ยังตั้งค่าไม่ครบยังบันทึกงานออกแบบได้ตามข้อสรุปเดิม แต่ฉบับที่จะเผยแพร่ใหม่ต้องไม่เหลือปุ่ม PoC ที่ดูเหมือนพร้อมอัปโหลดทั้งที่ยังไม่ตั้งค่า: Admin ต้องตั้งเป็นช่องแนบจริงให้ครบ หรือนำปุ่มที่ไม่ใช้แล้วออกด้วยตนเอง
- ไม่สร้าง file object จากค่าตัวอย่างในต้นแบบหรือ File ที่ทดลองเลือกใน PoC การบันทึก/เผยแพร่ต้นแบบของ Admin ไม่ใช่จังหวะอัปโหลดไฟล์ของ User

#### Published Form PoC เดิม

- คง Published Template, manifest, tag, required rules และสัญญาคำตอบเดิม ไม่เปลี่ยน text Field ให้รับ file object ย้อนหลัง และไม่เปลี่ยนปลายทางของคำตอบ/ประวัติเดิม
- ฟอร์มเดิมยังรับข้อมูลทั่วไปและใช้ Save Draft/Submit ตามสิทธิ์และ validation เดิมได้ ไม่ลด required หรือข้ามข้อผิดพลาดเพื่อให้การส่งผ่าน หากข้อกำหนดเดิมทำให้ดำเนินงานต่อไม่ได้ ต้องแจ้งข้อจำกัด ไม่แก้สัญญาย้อนหลังแทนผู้ใช้
- ปุ่ม PoC เดิมไม่เปิดอัปโหลดจริงและไม่แสดงว่าไฟล์ถูกบันทึกแล้ว ต้องแจ้งให้ใช้ Form ฉบับใหม่ที่ Admin ทำสำเนาและตั้งค่าเรียบร้อย หรือให้ติดต่อ Admin ไม่ปล่อยเป็นปุ่มที่กดแล้วเงียบ
- ไม่เดาว่าสำเนาใดเป็นปลายทางใหม่ ไม่ redirect หรือเปลี่ยน Form ของ Response อัตโนมัติ Admin ใช้การเผยแพร่/แชร์ลิงก์ของฉบับใหม่ตามวิธีเดิม
- ไม่ archive, ลบ Form หรือย้ายคำตอบอัตโนมัติจากการออกรุ่นนี้ สิทธิ์ archive เดิมของ Admin ยังคงอยู่ แต่ไม่ใช่ขั้นตอนที่แผนนี้บังคับให้ทำ
- เส้นทางทดลอง PoC ที่รับ File ไว้เฉพาะหน่วยความจำไม่ใช่ fallback สำหรับอัปโหลดจริง การคงฟอร์มเก่าไว้หมายถึงคงการทำงานของ Fields ตามสัญญาเดิม ไม่ใช่เก็บสัญญาอัปโหลดทดลองอีกชุด

#### คำตอบ ประวัติ และ File ที่เลือกค้าง

- Draft/Submission/Correction เก่ายังอยู่กับ Form และเอกสารฉบับเดิม ให้อ่านและแก้ไขภายใต้สิทธิ์/สัญญาเดิม ไม่ใช้ Correction เป็นช่องทางเปลี่ยนชนิด Field ของ Published Template
- ข้อความ ชื่อไฟล์ หรือ URL string เดิมยังเป็นค่าตามสัญญาเดิม ไม่สร้าง `file_link`/`file_token` ให้เอง ไม่ใช้เป็นหลักฐานว่า Folio อัปโหลดไฟล์ และไม่เพิ่มคำสั่งลบไฟล์ ECM โดยอนุมานจากข้อความเหล่านั้น
- การทำสำเนาคัดลอกเอกสารและการตั้งค่าต้นแบบ ไม่ย้าย Responses หรือคัดลอกคำตอบ/ไฟล์ของผู้ใช้ไป Form ใหม่อัตโนมัติ User เริ่มคำตอบในฉบับใหม่และเลือกไฟล์เอง
- File ที่เลือกค้างใน PoC ยังไม่ใช่ไฟล์ที่บันทึกแล้ว ไม่ย้าย File ข้าม Form/document scope หรือรับรองว่าจะกู้ bytes จากชื่อไฟล์ได้ ต้องแจ้งข้อจำกัดและเตือนก่อนการเปลี่ยนหน้าหรือการตั้งค่าที่ทิ้งรายการเลือกค้าง รักษางานอื่นที่ยังไม่บันทึกตาม flow เดิม ไม่ force reload เพียงเพื่อทำให้ guard ผ่าน
- เมื่อเข้า scope ใหม่ต้องเลือกไฟล์ใหม่ การเลือกใหม่นั้นยังไม่อัปโหลดจน User Save Draft/Submit และใช้สัญญา object จาก [สัญญา JSON ของไฟล์แนบและ URL ใน Excel](11-attachment-json-contract.md) ไม่รับค่าจาก PoC เป็น metadata ที่ server เชื่อถือ

#### งานที่ส่งต่อและหลักฐาน

- [วงจรไฟล์ร่างและการบันทึกโดยไม่สูญหาย](05-safe-draft-lifecycle.md) ใช้ขอบเขตการเปลี่ยนผ่านนี้กำหนดการบันทึก/ล้มเหลว โดยไม่ทำ migration ของคำตอบเดิมหรือเปิด upload ให้ text Field ของ Published Form เก่า
- [หน้าตั้งค่าปลายทางและสถานะไฟล์ที่ผู้ใช้เข้าใจ](08-admin-user-prototype.md) ต้องครอบคลุม Admin ตั้งค่าจากช่องเดิม, การแจ้งข้อจำกัดปุ่ม PoC ของฟอร์มที่เผยแพร่แล้ว และการเตือนเกี่ยวกับ File ที่ยังเลือกค้าง
- หลักฐาน runtime มีเพียงการเรียกคลาส PoC จริงด้วย File สังเคราะห์ตามบันทึกด้านบน ร่วมกับการอ่าน source ของการสร้าง Field และการทำสำเนา ไม่ใช่การทดสอบ UI/DB/ECM หรือยืนยันจำนวน/สภาพฟอร์มใน production
- [การใช้บัญชี ECM ร่วมโดยไม่ตัด token ของระบบอื่น](10-shared-ecm-login.md) ยังรอผู้ใช้ปรึกษาทีม ไม่มีการเลือกวิธี login หรือปิดหัวข้อนั้นแทน

ปิดเฉพาะนโยบายเปลี่ยนผ่าน ไม่ทำ migration ไม่ลบข้อมูล ไม่แก้ source/config ของระบบจริง และไม่มีการเรียก ECM
