# ระดับการตั้งค่าปลายทางไฟล์ของ Admin

Labels: wayfinder:grilling Type: grilling Parent: ../map.md Status: resolved Assignee: pyw1tt Blocked by: 01, 02, 09

## Question

เมื่อ Admin เลือก Document Category รายปุ่ม upload จาก API ตามสัญญาที่ตกลงแล้ว จะจัดการการตั้งค่าช่องเดี่ยวและคอลัมน์ตารางอย่างไร? ปุ่มในแต่ละแถวใช้การตั้งค่าร่วมระดับคอลัมน์หรือมีขอบเขตอื่น และใครกำหนด/แก้ค่า tag `fiscal_year` ที่ใช้เป็นปีงบประมาณในการอัปโหลด?

ตัดสินการเก็บร่างของการตั้งค่า ความครบถ้วนก่อนเผยแพร่ Form ผลเมื่อ category หายหรือใช้ไม่ได้ และว่า Admin เปลี่ยน category หลังมี Draft/Submission ได้หรือไม่ โดยไม่ขัด published-template immutability เดิมโดยไม่รับรู้ ต้องตรวจความสัมพันธ์ของสิทธิ์กับค่าปีงบประมาณ ไม่ถือว่าการอ่าน tag จากคำตอบอนุญาตให้ผู้กรอกเลือกปลายทางใดก็ได้

ข้อกำหนดที่ผู้ใช้ระบุแล้วอยู่ใน [ยืนยันสัญญา ECM ที่เอกสารยังไม่ตอบ](09-provider-contract-evidence.md): Admin เลือก category รายปุ่มจาก Document Category API, ปีมาจาก `fiscal_year` และ PM เป็นผู้สร้างโฟลเดอร์ ไม่ถามซ้ำว่าจะใช้รายการโฟลเดอร์อิสระหรือ category และไม่เพิ่มค่าปีงบประมาณอีกแหล่งโดยไม่มีข้อตกลง

## Prerequisites

## Current constraints

- [ADR 0004](../../../docs/adr/0004-results-filters-use-scalar-field-tags.md) กำหนด `fiscal_year` เป็น scalar tag สำหรับค้นหาผลลัพธ์ สัญญาแนบไฟล์ล่าสุดเพิ่มการใช้ค่าจาก tag นี้เป็น `documentYear`; ผู้ควบคุมค่าและการผูกกับแถวตารางยังต้องชัดเจน ไม่เปลี่ยนพฤติกรรมตัวกรองเดิมหรือสิทธิ์การเข้าถึงโดยอัตโนมัติ

## Comments

### Claim — 2026-11-12 — pyw1tt

เริ่มหารือการใช้ category รายปุ่มกับตาราง ผู้ควบคุมค่า `fiscal_year` และเงื่อนไขการตั้งค่าก่อน/หลังเผยแพร่ โดยยึดสัญญาล่าสุดในงานยืนยัน ECM ไม่ขอให้เลือกแหล่ง category หรือชื่อ tags ซ้ำ ขอบเขตยังเป็นการวางแผน ไม่แก้ application หรือข้อมูลจริง และยังไม่มี resolution

### Discussion — 2026-11-12 — ข้อสรุปรอบแรกจากผู้ใช้

- ช่องแนบเดี่ยวมี category ของตนเอง; ปุ่มในตารางใช้ category ร่วมต่อคอลัมน์ ทุกแถวรวมถึงแถวที่เพิ่มใหม่ใช้ค่าเดียวกัน แต่ละคอลัมน์เลือกต่างกันได้ ผู้กรอกเปลี่ยน category ไม่ได้
- `fiscal_year` เป็น scalar Field หนึ่งค่าระดับ Response ไฟล์ทุกช่องและทุกแถวในคำตอบใช้ปีเดียวกัน
- User กรอกหรือเลือก `fiscal_year` ตามกติกาของ Field ที่ Admin ตั้ง ไม่มีค่าปีของ storage อีกชุด
- Admin บันทึก Template Draft ที่เลือก category ยังไม่ครบได้ แต่เผยแพร่ไม่ได้จนช่องแนบทุกช่อง/คอลัมน์ตั้ง category ครบ
- category เป็นส่วนหนึ่งของสัญญาต้นแบบที่ล็อกหลังเผยแพร่ การเปลี่ยน category ต้องทำสำเนาเป็น Form ใหม่ ไม่เปลี่ยนปลายทางของ Draft/Submission ที่มีอยู่

ยังต้องตกลงเงื่อนไขตรวจหมวดก่อนเผยแพร่และพฤติกรรมเมื่อ API หมวดใช้งานไม่ได้ หรือหมวดเดิมหาย/เปลี่ยน จึงยังไม่ปิด ticket กติกาเมื่อ User เปลี่ยนปีหลังมีไฟล์ และการป้องกันชื่อชนอยู่ในงานชื่อไฟล์และวงจรไฟล์ตามเดิม

### Discussion — 2026-11-12 — การใช้รายการหมวดที่บันทึกไว้

- ผู้ใช้เลือกให้เผยแพร่จาก category ที่เคยเลือกไว้ได้ แม้ API รายการหมวดใช้งานไม่ได้ ไม่บังคับเรียกตรวจรายการสดก่อนเผยแพร่ แต่ยังต้องตั้ง category ครบตามข้อสรุปรอบแรก
- เวลา User Save/Submit ให้ใช้ category เดิมที่ผูกกับปุ่ม ไม่เรียกตรวจรายการ category ใหม่ก่อนอัปโหลด และไม่เปลี่ยนเป็นชื่อหมวดล่าสุดอัตโนมัติ
- หากทราบว่าปลายทางใช้ไม่ได้หรือ ECM ปฏิเสธหมวด ให้หยุดการอัปโหลดที่เกี่ยวข้องและแจ้งปุ่ม/หมวดที่มีปัญหา ไม่เลือกหมวดอื่นแทน ไม่แตะไฟล์เดิมอัตโนมัติ และไม่แก้สัญญา category ของ Form ที่เผยแพร่แล้ว
- เมื่อไม่ตรวจรายการซ้ำ Folio จะไม่ตรวจพบการหาย/เปลี่ยนชื่อของหมวดล่วงหน้า การบันทึกต้องไม่รายงานว่าอัปโหลดสำเร็จหาก ECM ปฏิเสธปลายทาง รายละเอียดผลลัพธ์บางส่วนและการกู้คืนอยู่ในงานวงจรไฟล์

เหลือยืนยันเงื่อนไขว่าต้นแบบที่มีปุ่มแนบต้องมี scalar Field tag `fiscal_year` ก่อนเผยแพร่ โดยไม่บังคับให้มีค่าคำตอบของ User ตั้งแต่ขั้นออกแบบ

### Resolution — 2026-11-12 — ยืนยันร่วมกับผู้ใช้

ผู้ใช้ยืนยันข้อสรุปรอบแรก นโยบายการใช้ category ที่บันทึกไว้ และเงื่อนไข scalar `fiscal_year` ก่อนเผยแพร่แล้ว ข้อสรุปนี้เป็นคำตอบสุดท้ายของหัวข้อ แทนสถานะที่ยังรอคำตอบในบันทึก Discussion ก่อนหน้า โดยไม่อนุญาตให้พัฒนาหรือเปลี่ยนข้อมูลจริง

#### ขอบเขตการตั้งค่า

- Admin เลือก category ให้ช่องแนบเดี่ยวแต่ละช่อง และให้คอลัมน์แนบแต่ละคอลัมน์ในตารางจากรายการตาม [สัญญา ECM ที่ยืนยันแล้ว](09-provider-contract-evidence.md)
- category ของคอลัมน์ใช้ร่วมกับทุกแถว รวมถึงแถวที่ User เพิ่มใหม่ ไม่ตั้งค่าแยกรายแถว แต่ละช่อง/คอลัมน์เลือก category ต่างกันได้
- User เลือกหรือเปลี่ยน category ไม่ได้ คำขออัปโหลดใช้ค่าที่บันทึกกับปุ่มในสัญญาฟอร์ม ไม่ใช้ปลายทางที่ User ส่งมาเลือกเอง
- `fiscal_year` เป็น scalar Field ระดับ Response หนึ่งค่า ไฟล์ทุกช่องและทุกแถวในคำตอบใช้ปีเดียวกัน User กรอกหรือเลือกปีตามกติกา Field ที่ Admin กำหนด ไม่มีค่าปีสำหรับ storage แยกอีกชุด

#### Template Draft และการเผยแพร่

- บันทึก Template Draft ที่ category ยังไม่ครบหรือยังไม่มี Field `fiscal_year` ได้ เพื่อเก็บงานออกแบบที่ยังไม่เสร็จ
- เผยแพร่ได้เมื่อทุกช่องแนบ/คอลัมน์แนบมี category ที่เคยเลือกจากรายการ API ครบ และมี scalar Field tag `fiscal_year` ในต้นแบบ ไม่บังคับว่าต้องมีค่าปีของ User ตั้งแต่ขั้นออกแบบ
- ไม่บังคับตรวจรายการ category สดก่อนเผยแพร่ ใช้ category ที่เคยเลือกและบันทึกไว้ได้ แม้ API รายการหมวดใช้งานไม่ได้
- เมื่อ API รายการหมวดใช้ไม่ได้ ห้ามล้างค่าที่เคยเลือกหรือเดาค่าใหม่แทน ยังเก็บร่างและเผยแพร่ได้ตามเงื่อนไขความครบถ้วนข้างต้น แต่การเลือก category ใหม่ต้องมีรายการ API ให้เลือก
- category เป็นส่วนหนึ่งของสัญญาต้นแบบที่ล็อกหลังเผยแพร่ หากต้องเปลี่ยน category ให้ทำสำเนาเป็น Form ใหม่ ไม่แก้ปลายทางของ Draft/Submission เดิมหรือย้ายไฟล์เก่าอัตโนมัติ

#### ขณะ User บันทึกหรือส่ง

- ใช้ category เดิมที่ผูกกับปุ่ม ไม่เรียกตรวจรายการ category ใหม่ก่อนอัปโหลด และไม่ตามการเปลี่ยนชื่อหมวดโดยอัตโนมัติ
- วิธีนี้ไม่รับรองว่าจะตรวจพบหมวดที่หายหรือเปลี่ยนล่วงหน้า หากทราบว่าปลายทางใช้ไม่ได้หรือ ECM ปฏิเสธ ให้หยุดการอัปโหลดที่เกี่ยวข้องและแจ้งว่าปุ่มใด/category ใดมีปัญหา ไม่ลองหมวดอื่น ไม่แก้สัญญาที่เผยแพร่แล้ว และไม่แตะไฟล์เดิมอัตโนมัติ
- การแก้ปัญหาหมวดอยู่ที่การประสาน PM เรื่องปลายทางเดิม หรือทำสำเนา Form ใหม่หากต้องเลือก category อื่น ไม่รายงานความสำเร็จของไฟล์ที่ ECM ปฏิเสธ

#### ขอบเขตที่ส่งต่อ

- [แหล่งเลขที่หนังสือยืนยันและกติกาชื่อไฟล์](04-confirmation-filename.md) ยังต้องตัดสิน scope ของ `docs_number`, ค่าว่าง/ค่าที่ไม่ถูกต้อง, ผลเมื่อเลขหรือปีเปลี่ยน และการป้องกันชื่อชน การใช้ปีเดียวทั้ง Response ไม่ได้ตอบว่าเลขหนังสือเดียวกันทั้ง Response
- [วงจรไฟล์ร่างและการบันทึกโดยไม่สูญหาย](05-safe-draft-lifecycle.md) ตัดสินผลเมื่ออัปโหลดสำเร็จบางช่อง การบันทึก/ส่งที่ล้มเหลว และการรักษางานเดิม ไม่ถือว่าการหยุดไฟล์ที่มีปัญหาอนุมัติให้บันทึกคำตอบแบบไม่ครบแล้วรายงานว่าสำเร็จ
- [ข้อกำหนดชนิดไฟล์และขนาดที่รับได้](07-pdf-acceptance.md) และ [การใช้บัญชี ECM ร่วมโดยไม่ตัด token ของระบบอื่น](10-shared-ecm-login.md) ยังเปิดตามเดิม
- [ADR 0004](../../../docs/adr/0004-results-filters-use-scalar-field-tags.md) ยังคงเดิม: `fiscal_year` เป็น scalar tag สำหรับกรองผลลัพธ์ การเพิ่มบทบาทให้ upload ไม่เปลี่ยนรูปแบบค้นหาหรือการดูประวัติโดยอัตโนมัติ

งานนี้เป็นการตัดสินใจผ่านการสนทนา ไม่ได้เรียก ECM จริง ไม่แก้ application/DB หรือทดสอบ runtime; ไม่มีการสร้างศัพท์โดเมนใหม่หรือเปลี่ยน ADR

### 2026-11-12 — เงื่อนไขเผยแพร่ที่เกี่ยวข้องเพิ่มเติม

ให้อ่าน [แหล่งเลขที่หนังสือยืนยันและกติกาชื่อไฟล์](04-confirmation-filename.md) ร่วมกับเงื่อนไขเผยแพร่ในหัวข้อนี้ งานนั้นเป็นเจ้าของข้อกำหนด tag `docs_number` และพฤติกรรมเมื่อ User เปลี่ยนเลขหรือปีหลังมีไฟล์ ไม่เปิดการตั้งค่า category หลังเผยแพร่หรือสร้างค่าปี storage แยกขึ้นมาใหม่

### Requirement amendment — 2026-11-12 — Tag ของปุ่มแนบไฟล์

ผู้ใช้ระบุให้ปุ่ม upload สร้าง tag อัตโนมัติเหมือน Field อื่น และให้ Admin แก้ชื่อ tag ได้ ใช้กติกาแก้ไข Template Draft เดิม ไม่เพิ่มการ rename tag ของ Form ที่เผยแพร่แล้วหรือให้ User เปลี่ยน tag เอง

- ใช้ pattern เดิมจาก `automaticUploadPocField` ใน [spreadsheet-upload-poc.js](../../../apps/onlyoffice-plugin/src/spreadsheet-upload-poc.js) ที่สร้าง `attachment_N` โดยเลี่ยงชื่อซ้ำ ไม่สร้าง convention การตั้ง tag อีกชุด
- ช่องเดี่ยวใช้ Field tag; ช่องในตารางใช้ tag ของคอลัมน์ตามโครงสร้างตารางเดิม แยกไฟล์แต่ละแถวด้วยตัวอ้างอิงแถว ไม่สร้าง tag ใหม่ทุกครั้งที่เลือกไฟล์หรือทุกแถว
- Admin เปลี่ยนชื่อได้ก่อนเผยแพร่ภายใต้กติกา Field/ความไม่ซ้ำใน scope เดิม ต้องบันทึก mapping และ metadata ของปุ่มให้ตรงกัน ไม่ผูกสิทธิ์หรือไฟล์กับชื่อ tag ที่ client เปลี่ยนมาเอง
- ใช้ binding identity เดิมประกอบการจับคู่ช่อง ไม่ทำให้การเปลี่ยนชื่อส่งไฟล์ไปผิดช่อง/แถว การผูก URL และ file token กับ JSON ให้ยึด [สัญญาข้อมูลเพิ่มเติม](09-provider-contract-evidence.md)

นี่เป็นข้อกำหนดต่อยอด PoC ไม่ใช่ผลยืนยันว่า PoC บันทึก URL/token หรือรองรับไฟล์ใน Correction แล้ว
